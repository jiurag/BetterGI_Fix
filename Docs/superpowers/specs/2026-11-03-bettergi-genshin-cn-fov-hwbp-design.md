# BetterGI 国服原神 FOV 硬件断点功能设计

## 1. 背景

BetterGI 当前已经通过 `GenshinFpsUnlockHook.dll` 提供国服原神去雾和帧率解锁。
去雾已改为线程硬件断点 Hook，不修改游戏代码页。历史提交 `05060025`
实现过 FOV，但后续提交 `207ee3b7` 删除了 FOV 界面、配置和运行期状态，
删除原因没有明确记录。

本设计恢复 FOV 功能，但不恢复旧版代码页字节补丁。FOV 和去雾一样使用
当前 Hook 管理器提供的硬件断点能力，避免重新引入“修改游戏代码页后触发
资源完整性校验”的风险路径。

本设计替代 `2026-11-02-bettergi-genshin-cn-fog-fov-hook-design.md`
中已经过期的 FOV 和共享布局内容；去雾现有行为不在本次改动范围内。

## 2. 目标

1. 仅对 BetterGI 启动的国服 `YuanShen.exe` 启用 FOV。
2. FOV 默认关闭，与去雾、帧率解锁分别启停。
3. 支持 `15～165` 的整数，默认 `60`，提供 `60`、`75`、`90` 三个预设。
4. 游戏运行中修改合法目标值后，不重启游戏即可生效。
5. 技能、大招、剧情和其他系统写入的非普通视角值原样放行。
6. FOV 安装失败时，仅 FOV 进入失败状态，去雾和帧率继续工作。
7. 状态和日志包含 FOV RVA、目标值、命中次数、替换次数、安装阶段和错误码。
8. 不修改游戏代码页，不修改磁盘上的游戏文件。
9. 使用自动化测试验证配置、布局、功能位和静态特征契约。
10. 使用黑盒步骤验证实际画面、镜头切换、动态修改和停止恢复。

## 3. 非目标

1. 不支持国际服 `GenshinImpact.exe` 的 FOV。
2. 不实现反作弊隐藏、检测绕过、进程隐藏或账号保护承诺。
3. 不保证游戏更新后特征仍然存在；校验失败时必须安全禁用 FOV。
4. 不对技能、大招和剧情镜头强制套用用户 FOV。
5. 不在自动化验证中启动 BetterGI 或原神。
6. 不在本功能中重新设计去雾、帧率解锁或普通注入流程。

## 4. 已核验依据

1. 本机国服配置为 `game_version=7.1.0`、`game_biz=hk4e_cn`。
2. 本机 `YuanShen.exe` 的 SHA256 为
   `7F89938DA606C1281659607D464702CDDB9A09A7D4320A196630F60A811EC38E`。
3. 旧 FOV 特征在当前 EXE 中只命中一次，入口 RVA 为 `0x0199BCD0`。
4. 当前入口前 17 字节与预期序言完全一致：

   ```text
   40 53 48 83 EC 60 0F 29 74 24 50 48 8B D9 0F 28 F1
   ```

5. 当前共享布局版本为 `5`，去雾功能位为 `1 << 0`，帧率功能位为 `1 << 1`。
6. 当前 `InlineHook` 已支持硬件断点安装、原始函数 trampoline、新线程补装、
   调试寄存器恢复和多个硬件断点对象。
7. 当前会话每 `62 ms` 刷新功能位并读取共享状态，因此可以复用同一周期更新
   FOV 开关和目标值。
8. 旧 FOV 公开逻辑只接受整数 `15～165`，默认 `60`，预设为 `60/75/90`。
9. 上述静态验证只证明当前二进制可以通过特征和入口预检，不能证明实际画面、
   技能镜头、剧情镜头或反作弊行为已经通过验证。

## 5. 方案选择

### 5.1 采用方案

扩展现有 `GenshinFpsUnlockHook.dll`，增加第二个硬件断点 Hook：

1. 去雾继续使用现有硬件断点对象和原始函数 trampoline。
2. FOV 使用独立的 `InlineHook` 实例和独立状态。
3. 两个 Hook 共用现有 Vectored Exception Handler 分发、线程补装和恢复机制。
4. 共享内存只追加 FOV 字段，并升级布局版本。
5. FOV 的任何失败不会中止帧率循环或去雾 Hook。

### 5.2 未采用方案

1. 恢复历史代码页内联 Hook：
   已有旧逻辑，但会重新修改游戏代码页，与当前去雾路线和资源完整性风险边界冲突。
2. 独立 FOV DLL：
   模块隔离更强，但需要第二次注入，并增加两个 DLL 的共享状态、线程断点和
   停止顺序协调，当前收益不足。

## 6. 用户界面

### 6.1 位置

在首页现有“启动设置”区域中，紧邻去雾设置增加 FOV 设置块，沿用现有卡片、
分隔线、开关、输入框和状态文字的视觉规范。

### 6.2 控件

1. “调整视野角度（FOV）”开关，默认关闭。
2. 整数输入框，默认显示已保存的合法值。
3. `60`、`75`、`90` 三个快捷按钮。
4. 状态文字显示“未启用”“已启用”“失败”或“已停止”。
5. 非法输入时显示行内错误提示。

### 6.3 交互

1. 空值、字母、小数、负数和范围外整数均不写入配置。
2. 最后保存的合法值在用户输入暂时错误时保持不变。
3. 点击预设按钮会更新输入文本，并通过正常校验流程写入合法值。
4. FOV 开关与去雾、帧率开关互不控制。
5. 输入暂时非法时只关闭 FOV 功能位，不停止当前会话；用户改回合法值后，
   下一轮共享状态更新重新启用 FOV。

## 7. 配置设计

在 `GenshinStartConfig` 中增加：

1. `MinFovTarget = 15`。
2. `MaxFovTarget = 165`。
3. `DefaultFovTarget = 60`。
4. `FovAdjustmentEnabled`，默认 `false`。
5. `FovTarget`，默认 `60`。
6. `IsFovTargetInputValid`，使用 `JsonIgnore`，默认 `true`。
7. `IsValidFovTarget(int target)`，仅接受闭区间 `15～165`。

`HomePageViewModel` 负责：

1. 保存输入框临时文本。
2. 使用不受区域设置影响的整数解析。
3. 实时更新输入合法性和错误文本。
4. 仅将合法整数写入 `FovTarget`。
5. 提供三个预设命令。
6. 展示 FOV 独立的运行期状态。

配置层不得直接访问游戏进程、共享内存或 Hook。

## 8. 共享内存契约

### 8.1 版本和功能位

1. 布局版本从 `5` 升为 `6`。
2. FOV 功能位定义为 `FovAdjustmentFeatureFlag = 1 << 2`。
3. C# 和 C++ 必须使用相同的版本、功能位和字段顺序。
4. 旧 DLL 与新宿主、旧宿主与新 DLL 均必须因版本不一致而拒绝运行期 Hook。

### 8.2 追加字段

在现有 `FogLastLayer` 之后按以下顺序追加，全部为四字节字段：

1. `FovStatus`：FOV 功能状态。
2. `FovRva`：FOV 函数 RVA，未定位时为 `0`。
3. `FovTarget`：当前合法目标整数。
4. `FovHookHitCount`：FOV 函数入口命中次数。
5. `FovReplaceCount`：实际替换 FOV 参数次数。
6. `FovInstallStage`：最近一次安装失败阶段。
7. `FovInstallError`：最近一次安装或恢复的 Win32/内部错误码。

不重排、不复用现有去雾字段。现有去雾诊断行为保持不变。

### 8.3 状态值

沿用现有共享状态值：

1. `0`：未请求。
2. `1`：已启用。
3. `2`：失败。
4. `3`：已停止。

### 8.4 并发访问

1. `FovTarget` 是单个 32 位整数，使用共享内存写入。
2. C++ 使用 `InterlockedCompareExchange` 读取目标值。
3. 目标值在 C++ 侧再次执行 `15～165` 夹取，非法值不安装或替换。
4. 统计字段使用 `InterlockedIncrement` 和 `InterlockedExchange` 更新。

## 9. 服务与会话

`GenshinFpsUnlockService` 的改动：

1. `HasEnabledRuntimeFeature` 增加 `FovAdjustmentEnabled`。
2. 当去雾、帧率和 FOV 全部关闭时停止会话。
3. 启动日志增加 FOV 开关和目标值。
4. 运行状态增加 FOV 独立状态。

`GenshinFpsUnlockSession` 的改动：

1. `CreateFeatureFlags` 仅在国服进程、FOV 开关开启、
   `IsFovTargetInputValid=true` 且 `FovTarget` 在合法范围时设置 `1 << 2`。
2. 创建共享内存时传入初始 FOV 目标。
3. 每个 `62 ms` 周期更新功能位、帧率目标和合法 FOV 目标。
4. 增加 FOV 状态发布、首次命中和首次替换日志。
5. Hook 就绪后若连续 `5` 秒没有命中，记录一次“已安装但未命中”警告。
6. 停止时等待整体共享状态进入 `Stopped`，不另建第二次注入或第二个 DLL。

FOV 单独开启即可启动会话；无需同时开启帧率解锁。即使用户把输入改成非法文本，
会话仍保持到 FOV 开关关闭或进程退出，以便改回合法值后无需重启游戏。

## 10. 游戏内 Hook 设计

### 10.1 目标特征

使用以下唯一特征定位 FOV 写入函数：

```text
40 53 48 83 EC 60 0F 29 74 24 ? 48 8B D9 0F 28 F1 E8 ? ? ? ? 48 85 C0 0F 84 ? ? ? ? E8 ? ? ? ? 48 8B C8
```

要求：

1. 只在主模块可执行代码节内查找。
2. 必须恰好命中一次。
3. 不以 `0x0199BCD0` 作为运行期兜底地址。

### 10.2 序言校验

使用以下 17 字节作为硬件断点安装前的完整入口校验：

```text
40 53 48 83 EC 60 0F 29 74 24 50 48 8B D9 0F 28 F1
```

任何字节不一致时：

1. 不安装断点。
2. 不生成或调用 FOV trampoline。
3. 将 FOV 状态写为失败。
4. 记录安装阶段、错误码和已定位 RVA。

### 10.3 调用约定

旧实现和当前序言对应的函数据此设计为：

```cpp
void __fastcall HookSetFieldOfView(void* instance, float value);
```

参数含义：

1. `rcx`：相机或渲染相关实例。
2. `xmm1`：本次请求的 FOV。

运行期必须通过原始函数 trampoline 调用原实现，禁止自行重写完整函数。

### 10.4 硬件断点

1. 创建独立 `g_fovFunctionHook`。
2. 调用 `InstallHardwareBreakpoint` 安装线程入口断点。
3. 使用与去雾相同的异常分发、trampoline 和新线程补装机制。
4. 每轮工作线程调用 `RefreshHardwareBreakpointThreads`，让新创建的线程获得断点。
5. FOV 与去雾各占一个调试寄存器槽位；槽位不足时只将对应新功能标记失败。
6. FOV 关闭或停止时，移除 FOV 断点并恢复各线程原调试寄存器。
7. 不修改 `.text` 代码字节，不刷新被替换的游戏指令。

### 10.5 替换策略

普通游戏基准值定义为 `45.0f`，比较容差为 `0.01f`。

以下情况替换为用户目标值：

1. Hook 首次命中。
2. 用户目标值发生变化后的首次命中。
3. 原请求与 `45.0f` 的绝对差不超过 `0.01f`。
4. 原请求与当前目标值的绝对差不超过 `0.01f`。

其他请求原样放行，包括技能、大招、剧情、瞄准和其他系统镜头。

替换规则不使用无条件覆盖，原因是旧实现对 `45` 正常视角和特殊脚本值进行了区分；
当前无法离线证明所有特殊镜头都使用同一个常量，因此保留这条保守边界。

### 10.6 动态目标与计数

1. 每轮读取共享内存 `FovTarget`。
2. 合法值变化时设置“下一次命中强制替换”标志。
3. 每次 FOV 入口命中递增 `FovHookHitCount`。
4. 每次将请求值改为目标值时递增 `FovReplaceCount`。
5. 命中或替换计数失败不得影响原函数调用。

## 11. 数据流

### 11.1 启动

1. BetterGI 启动国服原神并创建会话。
2. 会话创建布局版本 `6` 的共享内存，写入功能位和合法 FOV 目标。
3. 现有窗口消息 Hook 注入 `GenshinFpsUnlockHook.dll`。
4. DLL 定位帧率字段，将整体状态设为 `Ready`。
5. FOV 功能位开启时，工作线程扫描特征、校验序言并安装硬件断点。
6. FOV 安装成功后将 `FovStatus` 写为 `Ready`；失败时写为 `Failed`。

### 11.2 运行中更新

1. 用户修改 FOV 开关或合法目标值。
2. 服务保留现有配置对象，无需重建会话。
3. 会话下一轮将最新功能位和目标值写入共享内存。
4. DLL 下一轮读取新值。
5. 开启时安装或重新启用断点；关闭时移除断点。
6. 目标改变时强制下一次普通视角命中使用新值。

### 11.3 停止

1. 功能位关闭后，DLL 移除 FOV 硬件断点。
2. `FovStatus` 写为 `Stopped` 或 `NotRequested`。
3. 整个会话停止时依次处理 FOV、去雾、帧率。
4. FOV 恢复失败不得跳过去雾和帧率恢复。
5. 最后将整体状态写为 `Stopped`，会话释放共享内存。

## 12. 错误处理

1. 非国服进程：不设置 FOV 功能位，状态保持未请求。
2. 找不到可执行代码节：FOV 失败，不写猜测地址。
3. 特征匹配为零或多处：FOV 失败，记录错误码。
4. 17 字节序言不匹配：FOV 失败，记录 RVA 和安装阶段。
5. 硬件断点槽位不足：FOV 失败，去雾和帧率继续。
6. 异常处理回调中不得执行可抛出 C++ 异常的复杂逻辑。
7. 目标值非法：跳过本次替换，由宿主和 DLL 双重校验拦截。
8. FOV 断点恢复失败：FOV 标记失败，继续尝试去雾和帧率恢复。
9. FOV 失败后不得在每轮循环重复写满日志；只在状态或错误变化时记录。
10. 用户关闭 FOV 后清除本次安装失败标志；再次开启时允许重新扫描和安装。

## 13. 日志

固定记录以下信息：

1. 会话功能位和 FOV 目标值。
2. 国服识别结果。
3. FOV 特征匹配 RVA。
4. 硬件断点安装阶段和错误码。
5. 首次 FOV 命中次数和替换次数。
6. FOV 目标值动态变化。
7. FOV 停止和恢复结果。
8. 安装后观察窗口内零命中警告，每个会话最多一次。

不记录账号信息、大段进程内存或规避检测相关数据。

## 14. 测试设计

### 14.1 配置单元测试

1. 默认 FOV 开关为关闭。
2. 默认目标为 `60`。
3. `15` 和 `165` 合法。
4. `14`、`166`、负数和零非法。
5. 输入文本为空、字母和小数时保留上次合法值。
6. 三个预设分别产生 `60`、`75`、`90`。

### 14.2 功能位测试

1. 国服且 FOV 开启时设置 `1 << 2`。
2. 非国服时不设置 FOV 功能位。
3. FOV、去雾、帧率功能位可以任意组合。
4. FOV 目标非法时不设置 FOV 功能位。
5. 全部关闭时服务停止条件成立。
6. FOV 输入文本非法但开关仍开启时，功能位清除且当前会话不停止。

### 14.3 契约静态测试

1. C# 共享结构包含 `25` 个四字节字段，大小为 `100` 字节。
2. C++ 字段顺序与 C# 一致。
3. 布局版本为 `6`。
4. FOV 功能位为 `1 << 2`。
5. 17 字节序言在 C# 测试常量和 C++ 实现中一致。
6. 特征匹配器对唯一样本返回一个结果，对零命中和多命中返回失败。

### 14.4 构建验证

仓库根目录执行：

```powershell
dotnet msbuild BetterGenshinImpact.sln -restore -p:Configuration=Debug -nologo -tl:off -clp:ErrorsOnly
```

退出码必须为 `0`。Native DLL 使用仓库现有 `v143` 工程构建；若本机缺少对应
工具链，只能记录“本地未验证”，不能宣称构建成功。

### 14.5 黑盒测试

测试只通过界面开关、输入、游戏画面和日志判断结果，不读取或修改游戏内部状态。

1. FOV 关闭时启动，确认状态为未启用且画面与基线一致。
2. 只开启 FOV，默认 `60`，确认状态显示已启用。
3. 分别测试 `60`、`75`、`90`，确认视野变化方向正确。
4. 测试 `15` 和 `165`，确认可输入并应用，同时检查镜头裁剪和移动碰撞。
5. 输入 `14`、`166`、空值、字母和小数，确认显示错误且不应用。
6. 运行中从 `60` 改为 `90`，确认无需重启游戏即可变化。
7. 运行中关闭 FOV，确认下一次正常视角请求后恢复。
8. 开启 FOV 后释放技能、大招、瞄准、剧情和活动镜头，确认特殊镜头未被永久
   固定到用户目标。
9. 同时开启去雾、FOV 和帧率，确认三个状态均为已启用且功能互不干扰。
10. 关闭 FOV 后确认去雾和帧率仍在工作。
11. 关闭 BetterGI 或触发心跳停止，确认 FOV 断点恢复。
12. 长时间停留在固定场景并观察是否出现 `10010`、`10010-4001`、
    `EnetPingTimeout` 或 Hook 失败。该项只记录实际结果，不预设结论。
13. 游戏更新后重新执行特征唯一性和 17 字节序言静态核验；失败时确认 FOV
    安全禁用。

最终成功必须同时满足：

1. 普通视角按目标值变化。
2. 技能和剧情镜头未出现持续错误覆盖。
3. 关闭后恢复。
4. 去雾与帧率未受 FOV 失败影响。
5. 用户完成黑盒确认。

## 15. 风险与应对

1. 调试寄存器槽位冲突：
   FOV 和去雾各占一个槽位；槽位不足时只禁用对应功能并记录错误。
2. 游戏更新导致特征失效：
   特征唯一和 17 字节序言双重校验，失败时安全禁用。
3. 特殊镜头误判：
   只替换普通基准值和当前目标值，其他值放行，并通过剧情、技能和活动镜头黑盒验证。
