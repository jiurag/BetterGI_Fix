# BetterGI 国服原神去雾与 FOV 扩展设计

## 1. 背景与目标

BetterGI 现有帧率解锁会在 BetterGI 启动原神后，通过
`GenshinFpsUnlockHook.dll` 定位并持续写入动态帧率字段。本次在同一个注入会话中增加国服原神的引擎级去雾和 FOV 调节。

目标如下：

1. 保留现有帧率解锁行为，不新增第二次 DLL 注入。
2. 新增“去除场景雾”开关，默认关闭。
3. 新增“调整视野角度（FOV）”开关，默认关闭。
4. FOV 支持 `15～165` 的整数，默认 `60`，提供 `60`、`75`、`90` 三个快捷预设。
5. 帧率、去雾和 FOV 分别显示独立状态；去雾或 FOV 初始化失败时，帧率解锁继续工作。
6. 只在 BetterGI 启动国服 `YuanShen.exe`，且帧率解锁总开关开启时加载画面增强。
7. 去雾或 FOV 关闭后停止改写，并恢复已经修改的 Hook 指令。
8. 游戏退出、BetterGI 正常退出或心跳超时后停止所有改写。

## 2. 非目标

1. 本次不实现国际服 `GenshinImpact.exe` 的去雾和 FOV。
2. 不改变游戏文件，不修改磁盘上的 `YuanShen.exe`。
3. 不实现反作弊隐藏、进程隐藏、检测绕过或其他对抗能力。
4. 不承诺功能不会被检测，账号风险保持“未知/未验证”。
5. 不提供始终置顶、窗口缩放或全屏窗口化功能。
6. 不保证游戏更新后仍然可用；特征不匹配时本次画面增强必须安全禁用。
7. 不启动 BetterGI 或原神进行自动化运行期测试。

## 3. 已确认依据

1. 当前注入由 `WH_GETMESSAGE` 窗口消息 Hook 完成，工作线程和共享内存通道已经存在。
2. 当前共享内存前缀为 `Local\UnityPlayer.RuntimeState.<PID>`。
3. 当前 Hook DLL 已用 `GetModuleHandleExW` 固定，游戏退出前不会主动卸载。
4. 本机国服客户端为 `E:\Game1\hk4e_cn\YuanShen.exe`。
5. 本机国服版本为 `7.1.0.48145775`。
6. 本机国服客户端 SHA256 为
   `7F89938DA606C1281659607D464702CDDB9A09A7D4320A196630F60A811EC38E`。
7. 磁盘 `global-metadata.dat` 以 `MHY\0` 开头，当前不能按普通 IL2CPP metadata 离线解析。
8. 当前版本曾尝试的公开 dump 方法槽索引不能可靠映射到国服实现，因此不得使用此前得到的索引 `16911`、`17078` 或 `16371`。

## 4. 方案选择

### 4.1 采用方案

扩展现有 `GenshinFpsUnlockHook.dll`：

1. 帧率字段继续由现有后台线程定时写入。
2. 同一个共享内存增加功能位、FOV 目标值和各功能状态。
3. 去雾 Hook 和 FOV Hook 由同一个工作线程在国服进程内安装。
4. 每个功能先按唯一特征定位，再校验完整 Hook 序言，再写代码页。
5. 任一画面功能失败只更新自己的状态，不终止帧率写入。

### 4.2 未采用方案

1. 独立画面 Hook DLL：隔离性更高，但需要第二次注入，并增加模块加载、共享内存和卸载时序风险。
2. 直接写雾或 FOV 字段：去雾函数每次会复制 `0x194` 字节，直接写字段容易被覆盖；FOV 当前实例和生命周期也没有可靠离线解析依据，存在猜测地址风险。因此去雾改为 Hook 复制函数，FOV 继续 Hook 内部写入函数。

## 5. 安全启用与“伪装修饰”边界

本设计中的“伪装修饰”只指正常运行行为：

1. 只有进程路径以 `\YuanShen.exe` 结尾且确认当前进程 ID 匹配共享会话时，才初始化国服画面增强。
2. 只有对应开关开启时才安装该功能 Hook。
3. 特征必须全模块唯一，Hook 入口序言必须与预期指令逐字节一致。
4. 任一校验失败时不猜地址、不写代码页，只记录该功能失败。
5. 心跳超过 `5` 秒未更新时恢复帧率原值并移除画面 Hook。
6. 关闭开关时先停止对应改写，再恢复被替换的指令字节。
7. 恢复顺序为 FOV、去雾、帧率，避免恢复过程中仍有 Hook 进入失效代码。
8. Hook DLL 因现有固定机制继续驻留到游戏退出，不宣称已经卸载。
9. 运行期 DLL 使用随机临时文件名、通用导出名和通用共享内存前缀，仅降低固定特征暴露，不构成反作弊检测规避。

## 6. 去雾原理与算法

### 6.1 目标

在渲染线程复制国服雾参数结构时清除本次复制中的雾开关，不改写磁盘文件，也不长期修改游戏全局设置。

### 6.2 算法

1. 在当前国服客户端的 `.text` 节中按唯一特征定位雾参数复制函数，不依赖固定 RVA。
2. 当前核实版本的函数入口 RVA 为 `0x19C6230`，入口前 16 字节为：

```text
0F B6 02 88 01 8B 42 04 89 41 04 F3 0F 10 52 14
```

3. 反汇编确认该函数把 `0x194` 字节结构从 `rdx` 复制到 `rcx`，函数返回目标地址。
4. 全文件只有一处直接调用该函数；调用点传入的两个地址相差 `0x194`，与复制函数的长度一致。
5. 去雾开启时复制源结构到栈缓冲，把首字节置零，再交给原始函数执行复制。
6. 去雾关闭或心跳超时时移除内联 Hook，之后游戏按原始值复制结构，雾设置恢复。
7. 复制或调用异常时原样调用原始函数，禁止把失败扩散到渲染线程。
8. 特征、序言或 Hook 安装失败时只标记去雾失败，不中断帧率解锁和 FOV。

### 6.3 验证边界

1. 静态检查只能证明特征唯一、序言完整、调用点结构长度一致，不能代替画面效果验证。
2. 运行期 `FogStatus=Ready` 只能证明 Hook 已安装。
3. 最终成功必须同时满足：画面雾效消失、关闭后恢复、进程不崩溃。

## 7. FOV 原理与算法

### 7.1 目标

设计时观察到的国服 FOV 内部写入函数入口 RVA 为 `0x199C8D0`。运行时不依赖固定 RVA。

入口特征为：

```text
40 53 48 83 EC 60 0F 29 74 24 ? 48 8B D9 0F 28 F1 E8 ? ? ? ? 48 85 C0 0F 84 ? ? ? ? E8 ? ? ? ? 48 8B C8
```

在本机客户端中该特征只出现一次。高层入口 `0x1455150` 最终以尾跳转到该实现，但当前二进制中存在多个外形相似的高层 Setter，因此不使用高层通用序言定位。

### 7.2 调用约定

函数实际参数为：

1. `rcx`：相机或渲染相关实例。
2. `xmm1`：请求的 FOV 浮点值。
3. 返回值：无业务返回值。

因此 Hook 原型设计为：

```cpp
void __fastcall HookSetFieldOfView(void* instance, float value);
```

### 7.3 防止干扰技能与剧情

不无条件覆盖每次 FOV 请求：

1. 请求值为普通游戏视角基准 `45` 或当前目标值时，替换为用户目标 FOV。
2. 技能、演出和剧情写入的其他 FOV 值原样放行。
3. 用户修改目标值后强制执行一次替换，保证无需重启游戏。
4. 功能关闭时停止替换并恢复原始函数入口。
5. 该方法牺牲特殊镜头期间的目标值保持，换取剧情和技能镜头不被破坏。

### 7.4 取值范围

1. 合法范围：`15～165`。
2. 默认值：`60`。
3. 快捷预设：`60`、`75`、`90`。
4. Hook 内再次夹取值，避免共享内存写入非法值。
5. 目标值变化在下一轮共享内存轮询后生效，不要求重启游戏。

范围依据：参考项目 `genshin-unlock` 采用 `1～179`，综合解锁工具的国服界面采用 `15～165`。本次选择两者中更保守的 `15～165`，降低极端视野造成镜头碰撞、裁剪和界面异常的风险。默认 `60` 是设计决定，用于首次开启时提供轻微变化，而不直接跳到参考配置中的 `90`。

### 7.5 Hook 点

1. 在游戏主模块 `il2cpp` 节内按完整特征查找函数入口。
2. 复制并替换前 `17` 字节。
3. 前 `17` 字节由五条完整指令组成，不包含相对跳转或 RIP 相对寻址。
4. trampoline 先执行这 `17` 字节，再绝对跳回原函数 `+0x11`。

## 8. 用户界面

### 8.1 位置

在首页“启动时解锁帧率”设置块下方增加一个默认折叠的“画面增强（国服）”展开区域，避免继续增加常驻提示密度。

### 8.2 帧率总开关

1. 现有“启动时解锁帧率”仍是本次注入会话的总开关。
2. 总开关关闭时，帧率、去雾和 FOV 都不加载。
3. 总开关开启时，画面增强子项只在国服 `YuanShen.exe` 中生效。

### 8.3 去除场景雾

1. 显示固定开关“去除场景雾”。
2. 默认关闭。
3. 状态文字显示“未启用”“已启用”或具体失败原因。
4. 说明文字明确会改变天气、水面、远景和剧情场景的雾表现，需由用户黑盒确认。

### 8.4 FOV

1. 显示固定开关“调整视野角度（FOV）”。
2. 默认关闭。
3. 输入框允许 `15～165` 的整数，默认 `60`。
4. 提供 `60`、`75`、`90` 三个按钮。
5. 非法输入显示行内错误，不覆盖上次保存的合法值。
6. 状态文字分别显示“未启用”“已启用”或具体失败原因。

## 9. 配置

在 `GenshinStartConfig` 增加：

1. `FogRemovalEnabled`：去除场景雾开关，默认 `false`。
2. `FovAdjustmentEnabled`：FOV 开关，默认 `false`。
3. `FovTarget`：合法 FOV 值，默认 `60`。
4. `IsFovTargetInputValid`：当前输入框是否合法，不持久化。

增加范围、默认值和校验方法。页面临时非法文本不写入 `FovTarget`。

## 10. 共享内存契约

在原共享状态末尾追加四字节字段：

1. `LayoutVersion`：布局版本，本次为 `2`。
2. `FeatureFlags`：位 `0` 表示去雾开启，位 `1` 表示 FOV 开启。
3. `FovTarget`：当前 FOV 目标值。
4. `FramerateStatus`：帧率字段状态。
5. `FogStatus`：去雾 Hook 状态。
6. `FovStatus`：FOV Hook 状态。
7. `FogRva`：已定位去雾函数 RVA；失败时为 `0`。
8. `FovRva`：已定位 FOV 函数 RVA；失败时为 `0`。

功能状态定义：

1. `0`：未请求。
2. `1`：已启用。
3. `2`：失败。
4. `3`：已恢复并停止。

C# 和 C++ 结构继续使用 `Pack = 4`，字段顺序和顺序完全一致。C# 初始化时写入布局版本和功能位，C++ 发现版本不匹配时拒绝安装画面 Hook。

## 11. 架构与职责

### 11.1 配置层

`GenshinStartConfig` 只保存开关、目标值和输入合法性，不依赖 Hook 或游戏进程 API。

### 11.2 页面与 ViewModel

`HomePageViewModel` 负责：

1. FOV 文本、范围校验和错误提示。
2. `60`、`75`、`90` 三个快捷命令。
3. 页面展示文本。

ViewModel 不直接写共享内存，不执行地址扫描。

### 11.3 注入会话

现有 `GenshinFpsUnlockSession` 继续负责注入、心跳、等待和恢复。它只向共享状态写入合法功能位和目标值。

关闭总开关时，会话先请求游戏内停止，再等待所有状态恢复。

### 11.4 游戏内工作线程

`GenshinFpsUnlockHook.cpp` 负责：

1. 校验国服进程和共享内存。
2. 定位帧率字段。
3. 按功能位定位并安装去雾和 FOV Hook。
4. 每 `62ms` 更新帧率、读取功能位和 FOV 目标值。
5. 关闭功能时更新对应 Hook 状态。
6. 停止时按 FOV、去雾、帧率顺序恢复。

### 11.5 内联 Hook 管理器

新增专用最小化 x64 Inline Hook 管理器，职责仅包含：

1. 保存原始代码页保护。
2. 分配 trampoline。
3. 暂停除当前线程外的进程线程。
4. 写入绝对跳转并刷新指令缓存。
5. 恢复原始字节并释放 trampoline。

安装或恢复时，任何线程暂停失败都必须放弃本次代码页修改并恢复已暂停线程。该管理器不承担特征扫描或业务状态。

## 12. 数据流

### 12.1 启动

1. BetterGI 启动国服原神。
2. 现有会话创建共享内存并写入目标帧率、功能位和 FOV 目标值。
3. 现有窗口消息 Hook 注入 `GenshinFpsUnlockHook.dll`。
4. DLL 工作线程确认国服进程。
5. 定位帧率字段并保持现有写入行为。
6. 去雾功能开启时，定位并安装去雾 Hook。
7. FOV 功能开启时，定位并安装 FOV Hook。
8. 每个功能完成后独立更新状态，C# 轮询并记录结果。

### 12.2 运行中修改

1. 用户修改开关或合法 FOV 值。
2. 配置对象更新。
3. 会话在下一轮心跳前把功能位和目标值写入共享内存。
4. 游戏内工作线程读取后启用、停用或更新对应功能。

### 12.3 关闭

1. 关闭单个画面功能时，只停止对应改写并恢复对应 Hook。
2. 关闭帧率总开关时，请求整个游戏内会话停止。
3. 游戏内会话先移除 FOV Hook，再移除去雾 Hook，最后恢复帧率原值。
4. 状态分别写成已停止。
5. C# 等待会话结束并释放共享内存。

## 13. 错误处理

### 13.1 非国服进程

帧率功能继续按现有规则工作，国服画面增强状态保持“未请求”，不安装任何画面 Hook。

### 13.2 特征失败

1. 去雾特征不是唯一匹配：去雾状态写为失败，FOV 和帧率继续。
2. FOV 特征不是唯一匹配：FOV 状态写为失败，去雾和帧率继续。
3. 不记录或使用硬编码 RVA 兜底。

### 13.3 序言校验失败

1. 完整入口序言不符合设计字节时，不安装 Hook。
2. 状态写为失败，并记录入口 RVA 以便诊断。
3. 不写入任何代码页字节。

### 13.4 Hook 安装失败

1. 暂停线程失败、分配 trampoline 失败、修改保护失败或写指令失败时，恢复已经完成的步骤。
2. 只标记该功能失败，不终止帧率循环。

### 13.5 Hook 恢复失败

1. 恢复失败时保留 trampoline，禁止释放其内存。
2. 状态写为失败，不把 DLL 固定状态误报成已完全恢复。
3. BetterGI 记录警告并继续退出流程，不无限重试。

### 13.6 心跳超时

超过 `5` 秒未更新心跳时按整体停止处理，执行 FOV、去雾和帧率恢复。

## 14. 日志

记录以下信息：

1. 是否识别为国服进程。
2. 各功能开关状态。
3. 去雾和 FOV 唯一特征命中的 RVA。
4. 各功能启用、失败和恢复状态。
5. 失败阶段和 Win32 错误码。
6. FOV 目标值。

不记录大段内存内容、账号信息或用于规避检测的信息。

## 15. 黑盒测试策略

### 15.1 构建

只执行：

```powershell
dotnet msbuild BetterGenshinImpact.sln -restore -p:Configuration=Debug -nologo -tl:off -clp:ErrorsOnly
```

退出码必须为 `0`。不启动 BetterGI、不启动原神、不使用 `dotnet run`。

### 15.2 功能验收

1. 帧率总开关关闭，由 BetterGI 启动国服原神，确认去雾和 FOV 都不启用。
2. 帧率总开关开启，去雾和 FOV 都关闭，确认现有帧率解锁不受影响。
3. 只开启去雾，确认普通晴天、雨天、水边、远山和室内场景的雾表现变化。
4. 去雾开启时进入战斗、元素技能、角色界面、活动界面和剧情过场，确认没有黑屏、闪烁、贴图丢失或崩溃。
5. 运行中关闭去雾，确认场景雾在下一次雾参数更新后恢复。
6. 只开启 FOV 并设为 `60`，确认正常游玩视野变宽且角色移动、瞄准和镜头碰撞正常。
7. 分别测试 `15`、`60`、`75`、`90`、`165`，确认输入和应用一致。
8. 输入 `14`、`166`、空值、小数和字母，确认显示错误且不覆盖上次合法值。
9. FOV 开启时触发元素爆发、剧情过场和镜头切换，确认临时 FOV 不被永久强制为旧目标值。
10. 运行中把 FOV 从 `60` 改为 `90`，确认不重启游戏即可更新。
11. 运行中关闭 FOV，确认下一次正常稳定 FOV 请求恢复游戏视野。
12. 同时开启去雾和 FOV，确认两个功能可以共存。
13. 关闭帧率总开关，确认三个功能依次停止并恢复。
14. 正常退出 BetterGI，确认游戏继续运行且没有持续改写。
15. 结束 BetterGI 进程并等待超过 `5` 秒，确认游戏内 Hook 心跳超时并恢复。
16. 手动启动国服原神后再用 BetterGI 附加，确认不追加载入画面增强。
17. 用 BetterGI 启动国际服，确认帧率按现有逻辑工作，但去雾和 FOV 不加载。

### 15.3 失败路径验收

1. 将测试用二进制副本中的去雾特征改掉，确认只有去雾显示失败，帧率和 FOV 继续工作。
2. 将测试用二进制副本中的 FOV 特征改掉，确认只有 FOV 显示失败，帧率和去雾继续工作。
3. 确认日志记录失败阶段，不出现猜测地址后的强制写入。
4. 确认失败提示不会重复刷屏。

## 16. 风险与应对

1. 游戏更新导致特征变化：唯一特征和入口序言双重校验，失败时只禁用对应功能。
2. Hook 线程暂停不完整可能造成代码页修改竞争：先暂停所有可打开线程，任一失败即放弃修改。
3. 去雾影响剧情或水面：默认关闭，必须完成多场景黑盒验收。
4. FOV 只能区分普通基准视角、当前目标值和其它脚本值：普通视角恢复目标值，技能和剧情值原样通过。
5. FOV 关闭后如果游戏不再请求 FOV，视野可能暂时保持最后值：由下一次正常 FOV 更新恢复，验收必须覆盖。
6. 心跳超时与游戏更新同时发生时状态可能不完整：先移除 Hook，再恢复字段，所有失败只记录，不无限重试。
7. 反作弊风险未知：界面保留风险提示，不提供规避或隐藏能力。
