# BetterGI 原神启动帧率解锁设计

## 1. 背景与目标

BetterGI 的“原神，启动！”设置目前支持安装位置、启动参数、HDR、自动进入游戏和其他启动选项，但不提供帧率解锁。

本功能参考 Starward 已公开的 Genshin FPS Helper 原理，在 BetterGI 内使用 C# 完成地址定位、目标帧率写入和生命周期管理，不复制 Starward 项目，不依赖 Starward 程序，也不引入 Hook DLL。

目标如下：

1. 在首页“原神，启动！”卡片中新增“启动时解锁帧率”开关。
2. 新增可手动输入的整数帧率输入框，允许范围为 `30～240`，默认值为 `120`。
3. 新增“90 帧”和“120 帧”两个快捷预设按钮。
4. 只有原神由 BetterGI 启动，并且启动时开关已经开启时，才启动解锁。
5. 原神已经运行、手动选窗附加或由用户直接启动时，不因为开关开启而接管解锁。
6. 运行期间关闭开关时停止写入，并尽力恢复接管前的原值。
7. 原神退出、BetterGI 正常退出或解锁发生不可恢复错误时释放后台资源，避免残留写入线程。
8. 解锁失败不影响原神本身继续运行，也不阻断 BetterGI 的截图和任务流程。

## 2. 非目标

1. 不支持云原神网页版。
2. 不支持通过 BetterGI 修改已经运行且不是由 BetterGI 启动的原神。
3. 不修改游戏可执行文件，不注入 DLL，不安装键盘或窗口钩子。
4. 不实现反作弊检测规避、隐藏进程、隐藏内存操作或其他对抗能力。
5. 不支持大于 `240 FPS` 的目标值。
6. 不保证所有游戏版本、服务器或反作弊状态下的可用性。

## 3. 已知依据与限制

### 3.1 已核对的项目入口

1. 首页启动设置卡片位于 `BetterGenshinImpact/View/Pages/HomePage.xaml`。
2. 原神启动配置位于 `BetterGenshinImpact/Core/Config/GenshinStartConfig.cs`。
3. 本机原神启动和窗口等待位于 `BetterGenshinImpact/GameTask/SystemControl.cs` 的 `StartFromLocalAsync`。
4. 本机游戏运行环境位于 `BetterGenshinImpact/GameTask/Runtime/Win32/Win32RuntimeProvider.cs`。
5. 游戏 PID 可通过 `Win32GameWindow.ProcessId` 或窗口句柄反查进程获得。
6. BetterGI 启动时通过 `RuntimeHelper.EnsureElevated()` 请求管理员权限。
7. 配置根通过 `ConfigChangeTracker` 递归追踪属性变化并触发保存。

### 3.2 已确认的帧率解锁原理

Starward 的参考实现使用以下步骤：

1. 在原神主模块的 `il2cpp` 段中搜索字节特征 `B9 3C 00 00 00 E8`。
2. 从特征后的 `E8` 指令开始，沿相对调用或跳转链解析目标地址。
3. 最多跟随 32 层 `E8` 或 `E9`，直到遇到写指令 `89 0D <disp32>`。
4. 计算 `89 0D` 后的 32 位相对地址，得到帧率字段的绝对地址。
5. 校验字段位于可写内存区域。
6. 后台线程每 `62ms` 将目标帧率写入该字段。

本功能使用相同的特征和解析逻辑，但由 BetterGI 的受管后台线程执行 `ReadProcessMemory` 和 `WriteProcessMemory`。

### 3.3 已测量与未测量范围

1. 已在本机游戏版本 `7.1.0.48145775` 上验证 `120 FPS` 实际生效。
2. 已记录的特征 RVA 为 `0x6C4716C`，Setter VA 为 `0x1416A6840`，动态帧率字段 RVA 为 `0x54CD60C`。
3. 已使用 PresentMon 测得过约 `116～122 FPS` 的提交帧率。
4. `240 FPS` 尚未完成黑盒实测。
5. 当前显示器刷新率为 `200Hz`，即使软件目标写为 `240 FPS`，实际显示帧率也可能受刷新率、垂直同步和游戏内部行为限制。
6. 游戏更新后，特征、调用链或字段布局可能变化。
7. 远程内存修改可能被游戏或反作弊处理，是否触发风险尚未验证，不能提供账号安全保证。

## 4. 方案选择

### 4.1 采用方案

采用 BetterGI 内置 C# 远程内存写入器：

1. BetterGI 负责启动游戏并取得 PID。
2. BetterGI 在后台定位帧率字段。
3. C# 后台循环定时写入目标帧率。
4. 开关关闭时停止循环并尝试恢复原值。

选择原因：

1. 功能自包含，不要求用户安装 Starward。
2. 不需要新增 C++ Helper、DLL、Hook 或额外的二进制签名流程。
3. 开关可以直接控制后台写入生命周期。
4. 与 BetterGI 现有 Win32 游戏运行环境和管理员权限体系兼容。

### 4.2 未采用方案

1. Native Helper 加 Hook DLL：更接近 Starward 原实现，但需要额外 C++ 工程、二进制打包和签名维护，集成成本更高。
2. 调用 Starward 辅助程序：改动最少，但不是 BetterGI 自包含功能，并依赖外部程序和兼容版本。

## 5. 用户体验设计

### 5.1 控件位置

在首页“原神，启动！”卡片的展开内容中，将新功能放在“自动进入游戏”和“使用 CMD 启动游戏”之间。

该区域包含：

1. 标题：“启动时解锁帧率”。
2. 开关：控制启动时是否启用。
3. 输入框：输入 `30～240` 的整数。
4. “90 帧”按钮。
5. “120 帧”按钮。
6. 风险说明：“仅当原神由 BetterGI 启动时生效；使用前请自行评估账号风险。”
7. 输入错误提示：仅当输入不是合法整数或超出范围时显示。

### 5.2 默认值与预设

1. 默认目标帧率为 `120`。
2. 点击“90 帧”会立即把输入框和历史配置更新为 `90`。
3. 点击“120 帧”会立即把输入框和历史配置更新为 `120`。
4. 预设按钮是快捷填值，不限制用户使用其他合法数值。
5. 用户手动输入合法值后，当前配置和输入框保持一致。

### 5.3 输入校验

1. 只接受十进制整数，不接受小数、负数、空值、十六进制或其他文本。
2. 合法范围为 `30～240`。
3. 输入不合法时显示行内错误，不覆盖上次保存的合法目标值。
4. 如果启动时输入仍不合法，原神按普通模式启动，本次不启用解锁。
5. 运行中把输入框改成非法值时，后台继续使用上次保存的合法值，不写入非法值。
6. 运行中改为新的合法值时，后台在下一轮写入周期使用新值。

### 5.4 开关语义

1. 启动原神前开关开启且目标值合法：本次由 BetterGI 启动的游戏启用解锁。
2. 启动原神前开关关闭：本次启动不启用解锁。
3. 原神由 BetterGI 启动后，再关闭开关：停止后台写入并尽力恢复原值。
4. 原神不是由 BetterGI 启动时，再打开开关：不追加入侵当前游戏，只影响下一次由 BetterGI 启动的游戏。
5. 原神由 BetterGI 启动但启动时开关关闭，之后才打开开关：不追溯解锁本次游戏，只影响下一次启动。

## 6. 架构与职责

### 6.1 配置层

在 `GenshinStartConfig` 中新增两个持久化字段：

1. `FpsUnlockEnabled`：是否在 BetterGI 启动原神时启用解锁，默认 `false`。
2. `FpsUnlockTarget`：已保存的合法目标帧率，默认 `120`。

配置层不引用进程、线程或 Win32 API。页面输入的临时非法文本不写入配置。

### 6.2 页面与 ViewModel 层

`HomePageViewModel` 增加：

1. 输入框显示文本。
2. 输入校验错误文本和可见性。
3. “90 帧”和“120 帧”两个命令。
4. 启动前校验方法。

页面继续使用 MVVM 绑定。需要回写的开关和输入框使用 `Mode=TwoWay`；只读状态文本使用 `Mode=OneWay`。

### 6.3 启动编排层

`Win32RuntimeProvider.AcquireAsync` 负责判断本次是否由 BetterGI实际拉起原神。

流程如下：

1. 如果已经找到原神窗口，不启动解锁服务。
2. 如果没有窗口且允许联动启动，则调用 `StartFromLocalAsync`。
3. 启动成功后，通过窗口句柄取得本次游戏 PID。
4. 如果启动时开关开启且目标值合法，调用 `GenshinFpsUnlockService.TryStart`。
5. 解锁服务在后台处理，不阻塞截图器绑定和后续任务。
6. 如果解锁失败，原神和 BetterGI 的普通流程继续。

### 6.4 帧率解锁服务

新增 `GenshinFpsUnlockService`，作为进程级单例服务负责：

1. 持有当前解锁会话。
2. 记录当前会话是否由 BetterGI 启动。
3. 启动和停止后台写入器。
4. 响应开关关闭、进程退出和正常退出。
5. 保证同一游戏 PID 只有一个写入循环。
6. 对同一进程只显示一次失败提示。
7. 将关键状态写入 BetterGI 日志。

该服务不依赖首页可见性，也不会因为停止截图器而自动停止解锁。只要游戏仍由 BetterGI 启动且开关开启，写入可以继续。

### 6.5 地址解析器

新增独立地址解析职责，在后台执行以下步骤：

1. 使用管理员权限打开目标进程，并保留该会话的进程句柄。
2. 获取原神主模块的基址和大小。
3. 读取远程 PE 头，定位名为 `il2cpp` 的节。
4. 分块读取 `il2cpp` 节，搜索特征 `B9 3C 00 00 00 E8`。
5. 对每个候选位置解析 `E8` 和 `E9` 相对跳转，最多跟随 32 层。
6. 匹配 `89 0D` 写指令并计算帧率字段绝对地址。
7. 验证目标地址位于已提交且可写的内存区域。
8. 首次写入前读取并保存原始字段值。

分块读取用于避免一次复制整个节导致不必要的内存峰值。所有搜索和解析都在后台线程完成。

### 6.6 帧率写入器

写入器负责：

1. 每 `62ms` 读取当前已保存的合法目标值。
2. 使用一次 `WriteProcessMemory` 写入 32 位整数。
3. 检查游戏进程是否仍在运行。
4. 检查是否收到停止请求。
5. 在停止或游戏退出时结束循环。
6. 在进程仍存活时尽力把首次记录的原始值写回。

写入器不修改代码页，不写执行指令，只修改解析出的可写帧率字段。

## 7. 数据流

### 7.1 启动游戏

1. 用户在首页打开开关并输入或选择目标帧率。
2. ViewModel 将合法值写入 `GenshinStartConfig`。
3. 用户点击“启动”或由命令行动作触发游戏运行环境。
4. `Win32RuntimeProvider` 发现原神未运行并调用 `StartFromLocalAsync`。
5. 原神窗口出现后，Provider 取得 PID。
6. Provider 调用解锁服务，并明确传入“本次由 BetterGI 启动”这一上下文。
7. 解锁服务创建后台会话，解析地址并开始写入。
8. 截图器绑定继续进行，不等待地址解析完成。

### 7.2 修改目标帧率

1. 用户手动输入合法值或点击预设按钮。
2. 配置值更新并持久化。
3. 写入器下一轮循环读取新值并写入。
4. 不需要重启游戏或重建后台线程。

### 7.3 关闭开关

1. 用户把开关关闭。
2. 配置保存为关闭状态。
3. 解锁服务收到配置变化。
4. 写入器停止循环。
5. 如果游戏仍存活，尝试恢复原始字段值。
6. 释放进程句柄和会话资源。

### 7.4 游戏或 BetterGI 退出

1. 游戏退出时，写入器检测到进程结束并停止。
2. BetterGI 正常退出时，依赖注入容器释放单例服务。
3. 服务取消写入线程并释放句柄。
4. 如果应用被强制结束或崩溃，进程清理可能来不及执行，帧率字段可能停留在最后一次写入值。

## 8. 错误处理

### 8.1 输入错误

1. 非法输入显示行内错误。
2. 不覆盖上次保存的合法值。
3. 启动时存在非法输入则本次跳过解锁，但原神仍正常启动。

### 8.2 权限错误

1. BetterGI 已在启动时申请管理员权限。
2. 如果仍无法打开进程，记录日志并向用户提示一次。
3. 不尝试绕过进程权限，不更改游戏安全设置。

### 8.3 特征或字段查找失败

1. 记录失败阶段，例如 PE 读取、`il2cpp` 节查找、特征查找、调用链解析或可写校验。
2. 不猜测地址，不使用以前版本硬编码 RVA 强行写入。
3. 本次解锁结束，原神继续运行。

### 8.4 写入失败

1. 停止当前解锁会话。
2. 尝试关闭并释放进程句柄。
3. 记录 Win32 错误码。
4. 同一游戏进程只提示一次，不进行无限弹窗或忙循环。

### 8.5 恢复失败

1. 开关关闭后如果无法恢复原值，记录日志。
2. 不为了恢复而反复写入或延长关闭流程。
3. 用户界面保持开关关闭状态，下一次由 BetterGI 启动时不会继续写入。

## 9. 日志与可诊断性

日志只记录必要信息：

1. 是否由 BetterGI启动。
2. 目标进程 PID。
3. 目标帧率。
4. 解析阶段和失败原因。
5. 是否找到帧率字段。
6. 是否开始、停止或恢复失败。
7. 不记录大段内存内容，不记录账号信息。

日志用于用户排查和黑盒验证，不作为账号安全的保证。

## 10. 测试策略

### 10.1 构建验证

在仓库根目录执行：

```powershell
dotnet msbuild BetterGenshinImpact.sln -restore -p:Configuration=Debug -nologo -tl:off -clp:ErrorsOnly
```

退出码必须为 `0`。

不启动 BetterGI 主程序、不使用 `dotnet run`、不通过 IDE 启动主程序作为编译验证。

### 10.2 黑盒验收

运行期验收由用户实际操作 BetterGI 和原神，外部使用 PresentMon 观察结果。

1. 开关关闭，由 BetterGI 启动原神，确认不会启动解锁会话，帧率保持游戏默认水平。
2. 开关开启，输入 `90`，由 BetterGI 启动原神，确认实际帧率接近 `90 FPS`。
3. 游戏运行中点击“120 帧”，确认不重启游戏即可接近 `120 FPS`。
4. 游戏运行中手动输入其他合法值，确认下一轮写入采用新值。
5. 输入 `29`、`241`、空值、小数和字母，确认显示错误，不把非法值写入配置。
6. 开关开启时先手动启动原神，再通过 BetterGI 附加，确认不会解锁。
7. 开关关闭时由 BetterGI 启动原神，再打开开关，确认本次游戏不追溯解锁。
8. 解锁运行中关闭开关，确认后台停止写入并记录恢复结果。
9. 关闭原神，确认写入会话结束且 BetterGI 可再次正常启动游戏。
10. 正常退出 BetterGI，确认后台线程和进程句柄被释放。
11. 输入 `240` 启动游戏，使用 PresentMon 记录提交帧率。
12. 在 `240` 目标下检查实际显示效果，并结合当前 `200Hz` 显示器记录受刷新率限制的结果。

### 10.3 验收判定

1. 编译命令退出码为 `0`。
2. 首页能看到开关、输入框和两个预设按钮。
3. 合法输入、非法输入、预设按钮和配置持久化符合设计。
4. 只有由 BetterGI 启动的游戏会在启动时启用解锁。
5. 同一游戏 PID 没有重复写入循环。
6. 开关关闭、游戏退出和 BetterGI 正常退出后，不留下持续写入线程。
7. `90` 和 `120` 以 PresentMon 的外部测量结果为准。
8. `240` 是否达到必须单独报告实测值，不能用“已实现写入”代替“已达到 240 显示帧率”。

## 11. 风险与应对

1. 游戏更新导致特征变化：不猜测地址，解析失败时禁用本次解锁并记录原因。
2. 反作弊风险未知：界面明确提示风险，不提供规避和隐藏方案，不承诺账号安全。
3. `240 FPS` 可能受显示器或游戏限制：保留输入值，但以 PresentMon 和实际显示结果判断。
4. 强制结束 BetterGI 无法执行恢复：在文档和关闭流程中明确限制。
5. 多次触发启动可能产生重复会话：服务按 PID 去重，已存在同 PID 会话时不重复创建。
6. 远程读取可能造成启动延迟：解析完全在后台执行，不阻塞截图器。
7. 游戏进程退出瞬间写入可能失败：把进程退出视为正常停止原因，不进行无限重试。

## 12. 计划修改位置

1. `BetterGenshinImpact/Core/Config/GenshinStartConfig.cs`：新增开关和目标帧率配置。
2. `BetterGenshinImpact/ViewModel/Pages/HomePageViewModel.cs`：输入文本、校验、预设命令和启动前校验。
3. `BetterGenshinImpact/View/Pages/HomePage.xaml`：开关、输入框、预设按钮、错误提示和风险说明。
4. `BetterGenshinImpact/GameTask/Runtime/Win32/Win32RuntimeProvider.cs`：仅在 BetterGI 拉起游戏时调用解锁服务。
5. `BetterGenshinImpact/GameTask/Runtime/Win32/`：新增帧率解锁服务、地址解析器和写入能力。
6. `BetterGenshinImpact/App.xaml.cs`：注册解锁服务单例和必要的依赖。
7. 相关国际化资源：新增界面文本，若项目当前机制要求同步维护。

实际实现可在不改变上述职责边界的前提下调整文件名，但不得把内存操作放进 ViewModel，也不得让配置模型依赖解锁服务。
