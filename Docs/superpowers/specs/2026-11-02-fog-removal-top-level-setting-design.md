# BetterGI 去雾独立顶层设置设计

## 1. 背景与目标

当前主页把“去除场景雾”放在“画面增强（国服）”展开项中，位置又紧接在帧率解锁设置之后，界面上容易让人理解成帧率解锁的子功能。

实际行为中，去雾和帧率解锁是两个独立开关：

1. 分别由 `FogRemovalEnabled` 和 `FpsUnlockEnabled` 控制。
2. 任一功能开启都会创建运行期会话并加载同一个 `GenshinFpsUnlockHook.dll`。
3. 注入模块内部使用不同功能位，两个功能可以独立启用或关闭。

本次目标是只调整主页信息层级，让去雾成为与帧率解锁、全屏窗口化同级的独立设置项。

## 2. 非目标

1. 不拆分注入 DLL。
2. 不新增第二次 DLL 注入。
3. 不修改 `FogRemovalEnabled` 配置字段。
4. 不修改去雾 Hook、帧率字段写入或共享状态协议。
5. 不调整去雾算法，也不承诺消除账号风险或错误码。

## 3. 界面方案

采用独立顶层设置行。

1. 删除“画面增强（国服）”展开项。
2. 在帧率解锁设置之后增加独立设置行。
3. 标题显示“启动时去除场景雾”。
4. 说明显示“仅当 BetterGI 启动国服原神时生效；使用前请自行评估账号风险。”
5. 状态文本继续绑定 `FogRemovalStatusText`。
6. 开关继续双向绑定 `Config.GenshinStartConfig.FogRemovalEnabled`。
7. 设置行使用现有主页的 `Grid`、`Separator`、`ToggleSwitch` 样式，不新增视觉组件。

调整后的主页顺序为：

```text
启动时全屏窗口化
启动时解锁帧率
启动时去除场景雾
使用 CMD 启动游戏
```

去雾不再是帧率解锁的子项，也不是其他功能的展开子项。

## 4. 组件与数据流

1. `HomePage.xaml` 只负责调整布局和绑定位置。
2. `HomePageViewModel` 继续提供 `FogRemovalStatusText`，无需修改。
3. `GenshinStartConfig.FogRemovalEnabled` 继续保存开关状态，无需修改。
4. `GenshinFpsUnlockService` 继续在任一运行期功能开启时创建会话，无需修改。
5. `GenshinFpsUnlockHook.dll` 继续根据功能位分别处理帧率和去雾，无需修改。

数据流保持不变：

```text
去雾开关
  -> FogRemovalEnabled
  -> 运行期功能位
  -> 同一个 Hook DLL
  -> 去雾参数复制 Hook
  -> FogRemovalStatusText
```

## 5. 错误处理

1. 布局调整不新增运行时错误来源。
2. 开关仍使用现有双向绑定和状态更新机制。
3. 去雾失败时继续显示现有失败状态，不影响帧率解锁状态显示。
4. 不通过禁用其他开关来掩盖去雾失败。

## 6. 验证

1. 构建 `BetterGenshinImpact`，确认 XAML 编译通过。
2. 打开主页，确认去雾是独立设置行，不再出现“画面增强（国服）”展开项。
3. 依次切换帧率解锁、去雾和全屏窗口化，确认三个开关互不联动。
4. 使用现有去雾单元测试，确认配置和运行期功能位行为未回归。
5. 不启动游戏时只验证界面层级和构建结果；运行期效果需要另行进行黑盒启动测试。

## 7. 风险

1. 主页设置区域会稍长，但比保留展开项更直观。
2. 两个功能仍共用一个 DLL，因此界面独立不代表注入文件独立。
3. 共用 DLL 的账号风险不变；本次界面调整不会降低或被证明降低检测风险。
